# Nutcracker Simulator

Roblox simulator (Luau + Rojo). Round 01 = one playable area: crack nuts, earn coins, buy Strength.
Design reference and open questions: `docs/NUTCRACKER_REFERENCE_SPEC.md`.

## Commands

```bash
rojo build -o build/NutcrackerSimulator.rbxlx   # full place file, open it in Studio and press Play
rojo serve                                      # live sync; connect with the Rojo plugin in Studio
```

No linter/formatter/test runner is installed. Validation = `rojo build` + Play in Studio.

## Layout

```
src/shared  -> ReplicatedStorage.Shared
  Config.luau    all balance data: nut types, ranges, tick, strength/cost curves
  Format.luau    1234 -> "1.2k"
  Remotes.luau   declares remotes (folder "Net"): BuyStrength (RemoteFunction), Notify (RemoteEvent)
src/server  -> ServerScriptService.Server (init.server.luau boots the modules in order)
  SelfCheck      asserts on Config at boot
  MapBuilder     builds workspace.Map from Parts, returns nut spawn points
  NutModel       builds a nut Model from a Config `look` table
  PlayerData     coins + strength level per player (session only), mirrored to attributes/leaderstats
  NutService     spawn, assign (ClickDetector), auto tick damage, manual hits, break, reward, respawn
  ShopService    BuyStrength handler
src/client  -> StarterPlayerScripts.Client
  Effects        world feedback (pop, damage numbers, shards, highlight, sounds)
  Hud            ScreenGui built in code: stats, target card, shop, popups
```

## Rules of the architecture

- Server is the only authority. Clients read replicated state and never send amounts, ids or prices.
  - Player state: attributes on the Player (`Coins`, `Strength`, `StrengthLevel`, `TargetId`).
  - Nut state: attributes on each Model in `workspace.Nuts` (`NutId`, `Health`, `MaxHealth`).
- Every attack goes through `check()` in NutService (nut alive, player alive, range, strength >= resistance).
- New nut type = new entry in `Config.Nuts` + its name in `Config.NutOrder`. No new code.
- Map and UI are generated by code; there are no external assets or place-file-only instances.
- Gameplay decisions already taken: Hybrid + Assign (click assigns, server auto-hits each tick, clicking the
  assigned nut again adds a manual hit, walking away cancels). Do not change without the owner's approval.
